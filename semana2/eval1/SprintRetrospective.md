# Sprint Retrospective – Sistema Inteligente de Monitoreo Ambiental

## ¿Qué salió bien?

- Se definió un Product Backlog con historias de usuario claras.
- Se redactaron criterios de aceptación utilizando Gherkin.
- Se implementó la metodología TDD (Red → Green → Refactor) para el desarrollo.
- Se configuraron herramientas de calidad como Pytest, Ruff y MyPy.
- Se alcanzó una cobertura de pruebas superior al 80%.

---

## ¿Qué se puede mejorar?

- Planificar mejor el tiempo dedicado a cada historia de usuario.
- Escribir pruebas más completas para cubrir casos límite.
- Reducir el tiempo invertido corrigiendo errores de configuración.
- Mantener una mayor consistencia en los nombres de variables y funciones.

---

## Acción para el siguiente Sprint

En el siguiente Sprint se comenzará cada historia escribiendo primero los criterios de aceptación y los tests antes de implementar el código, con el objetivo de reducir retrabajos y mantener un flujo de desarrollo más organizado.
